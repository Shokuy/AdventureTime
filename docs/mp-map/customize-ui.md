# customize-ui

## Summary
All three areas were read and nothing was edited. (1) createHero() at src/three/models/hero.ts:79 takes no arguments, and every color is hard-coded from PAL (src/three/gfx.ts:183-186) or from inline hex values. Adding an optional `look: Partial<HeroLook> = {}` parameter keeps all 12 call sites compiling unchanged. Player3 (src/three/game/player.ts:69) is the only gameplay caller. About 10 color slots can be recolored cheaply. The hat, pants and sleeves need small geometry or material swaps. There is no backpack and no accessory slot today. Main pitfalls: per-rig `Mats` deduplicates materials by hex code; the geometry cache is global; nothing is disposed; and `heroLimbs()` finds limbs by Y position. (2) All UI is drawn on one 2D canvas (#ui) in a 1280x720 logical space. Mouse position is mapped by `toLogical` in src/main3d.ts:40. There is no DOM overlay and no text-entry widget. Recommended: one real `<input>` element (src/ui/textfield.ts) placed over a canvas-drawn frame using RT.ox/oy/scale. This needs a guard in the input.ts keydown handler, which currently calls preventDefault on Space, Backspace and the arrow keys, and maps WASD, Esc and Enter to game actions even while typing. Chat should be a global overlay hooked in main3d.ts, not inside a scene. (3) Pointer lock is requested only at src/three/game/level.ts:819 and released at level.ts:749, 802, 884 and 910. Esc is mapped to both 'pause' and 'back'. While the pointer is locked, the browser consumes the first Esc to exit the lock. Pause stops the entire simulation (level.ts:813-816), which must change for multiplayer. Release the lock when chat opens, and let Enter-to-send re-lock from inside the keydown handler.

## Risks
- Pointer lock and Esc behavior differs by browser: Chrome usually swallows the Esc keydown that ends the lock, and after a user Esc it refuses a new lock for about 1s (the promise rejection is unhandled, input.ts:65). Test Chrome, Firefox and Safari before relying on Esc to close the chat.
- If the guard in input.ts keydown (92-101) is skipped, typing in any DOM field moves the hero, triggers the pause/back actions, and loses Space and Backspace. Because keys are mapped by e.code, a Cyrillic keyboard layout does not avoid this.
- heroLimbs() (scenes3d.ts:1032-1039) finds limbs by Y position (0.18, 0.435) among body's child Groups. Any accessory Group at those heights silently breaks the ending cutscene.
- Within a rig, Mats.get deduplicates by hex code (kit.ts:57-62). Two customized slots with the same color share one material, so a runtime recolor hits both. Use Mats.own for customizable slots or rebuild the rig.
- Nothing is disposed: rigs, per-rig materials and canvas textures (hero.ts:70-77, 204-205, 242-257) leak on every rig rebuild and player join/leave. Rig (rig.ts) has no dispose(). Cached geometries are global and must not be disposed.
- A look received from another player drives material and geometry choices. Validate it (hex regex /^#[0-9a-f]{6}$/i, enum whitelist for hat and accessory, name length and charset) before calling createHero. Limit the chat text length, and render chat only on the canvas, never through innerHTML.
- save.reset() (save.ts:84-86) wipes everything except settings, so a look or name stored elsewhere in SaveData disappears on 'Новая игра'.
- Pausing stops the entire simulation (level.ts:813-816), and Game.update skips scene updates during fades (game.ts:87). Both stall a host-authoritative world for every client unless they are decoupled.
- draw.ts wrap() (123-136) splits only on spaces. Long chat tokens overflow the chat box, and measuring text every frame for a long log adds CPU cost.
- Out of scope but relevant to the Bluetooth gamepad request: input.ts pollPad (150-168) loops over all pads, so the last pad's sticks overwrite earlier ones. It never checks `p.mapping === 'standard'`, and a DualShock or DualSense over Bluetooth can report a non-standard mapping in Firefox and Safari, with different button and axis indices.
