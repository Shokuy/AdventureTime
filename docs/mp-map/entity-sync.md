# entity-sync

## Summary
Read-only audit of every dynamic entity in src/three/game for host-authoritative co-op. Nothing was edited.

Model the audit assumes: the host runs all enemy, boss and arena logic. Clients show enemies as puppets driven by snapshots plus reliable events. Each client checks hits on its own hero against those puppets, since all damage code currently targets L.player.

1. **Level builds are almost deterministic, with one exception that affects gameplay.** World geometry uses seeded random generators (world/kit.ts rng and hashSeed, srand(77) in the library). Build-time Math.random() only affects:
   - **Noodle3.t (objects.ts:253):** this changes the swing phase and the grab timing. It must be fixed.
   - **Soldier3 yaw (enemies.ts:206):** sets starting facing and the vision cone. It only matters until the host's first snapshot arrives.
   - **Visual-only differences:** BookBat3 colour (enemies.ts:1016) and the jar jam flavour on breakables (breakables.ts:28).
   - **The rest:** AI timers the host owns, or idle animation phases that don't matter.

   Builds also read inputs that differ per client: `seen`, `save`, and the `easy` setting. The host must send these before a client builds the level.

2. **Enemy IDs today.**
   - Level3D.enemy() and addEnemy() assign `'e'+enemySeq` only while the level is being built, in build order.
   - Arena wave enemies get `${arenaKey}_${wave}_${i}`, where arenaKey is `arena<round(cx)>_<round(cz)>`.
   - These keys exist to stop crumb farming, not for networking. KingChaser3 sets e.key to null when it tramples an enemy, and dead enemies are removed from L.enemies, so array indices shift.
   - Runtime spawns get no key at all: Jelly3 splits, SpagMonster3 rage meatballs, and SummonCrew boss summons. Bomb3, Shot3, Faller3, Wave3, BowlBall, Lane and dropped Pickup3 have no ID of any kind.
   - Proposal: add an Enemy3.netId. Build-time enemies use the same build-order counter on every client; runtime spawns get host-allocated IDs from a separate range, sent in the spawn event.

3. **Snapshot proposal.** Positions as int16 ×64 (±512 m covers every level), angles as u8.
   - Soldier family: [id, x, y, z, yaw, animState, speed, p, look, aware, sus], plus a stripe byte for Charger3. About 14 bytes.
   - Meatball3, BookBat3: [id, x, y, z, yaw].
   - Jelly3: adds `sq`. Spitter3: adds a 3-value state. Blocker3: adds state and speed.
   - Bosses get their own records (described in the items).
   - Flash, spawn scale, alert timer, roll, flap, aura, talk and shadows can all be derived on the client from events and the local clock.

4. **Reliable events.**
   - Host to clients:
     - enemies: spawn, die, hit result, bark
     - projectiles: shot, bomb and faller spawns, wave spawns
     - arenas: start, wave, done
     - level objects: breakable smash, noodle cut, checkpoint lit, trigger, chase prop smash, wall burst
     - bosses: grab, release, chomp, damage, phase, dizzy, die, heart drop, bowling-ball spawn and hits, summon carry and throw
   - Clients to host: hit requests, noise, grab break-free, bomb bat, shot reflect.

The risks list covers host-side behaviour that blocks this design: hitstop and slow-motion freeze the host's simulation, attack IDs collide across players, respawn rebuilds the whole level, and boss and enemy code assumes a single player.

## Risks
- Host world freezes during hitstop, freeze and slowT (level.ts:573, 596, 822-824). Left as is, every host-side hit, reflect or boss death pauses or slows the simulation for all peers.
- Noodle3.t=rand(0,10) at objects.ts:253 is the one build-time random value that affects gameplay: swing phase and grab timing differ per client.
- Clients only build identical levels (and therefore identical netIds) if they get the host's `seen`, checkpoint and easy flag before building. Boss hp and speed depend on save.data.settings.easy (throneBoss.ts:104, boss.ts:128).
- Enemy keys are not network IDs. KingChaser3 sets key=null on trample (boss.ts:245); runtime spawns (Jelly split, Spag meatballs, SummonCrew) get no key; L.enemies is spliced on death.
- Attack-id dedupe (lastHit, hitIds, hit, faceHit, lastAtk) will collide across players unless namespaced by player id.
- Victim-side damage only works if puppet rig and anim match the host exactly. That holds for SpagMonster3 rig.segments() and the BossHand box(), but it requires sending SpagAnim.target and the hand yaw/state every snapshot.
- SummonCrew overwrites enemy root transforms after Enemy3.sync (bossParts.ts:296-327 runs after level.ts:831). Puppets for carried enemies must be driven only by CREW_GRAB/CREW_FLING, or the visuals will fight.
- Cutscene scripts mutate boss, chaser and feast-king state directly with time-based tweens (scripts.ts:281-285, 349-357, 404-512). Running them on every client and on the host at once can diverge; the host's run must stay authoritative, and client copies should only affect camera and dialog.
- The grab break-free check reads local input on the host (throneBoss.ts:1092 input.pressed('attack')), and Player3.updateGrabbed handles grip on the grabbed hero. This must become client-side logic plus a GRAB_BREAK message.
- Shield3 block and sneak-attack ×2 decisions need the attacker's position, kind and from.y in the hit request (enemies.ts:491-499, 660-685), or melee feel will be wrong.
- Arena gate colliders (level.ts:305, 702, 721) can lock co-op players outside the ring or inside it. The start condition currently checks only one hero.
- Per-player instanced loot means E_DIE, BREAK_SMASH and ARENA_DONE must be reliable, or a client silently loses drops. The KingBoss3 dropHeart director gift (throneBoss.ts:321-345) is keyed to the host hero's hp history.
