## Summary

I looked at the story flow, the main loop, the Level3D lifecycle, every script, the other scenes, the singletons and the testkit. No files were edited.

The core finding: the engine assumes one local hero and one owner of the world. Three things in the code show this.
1) `L.player` is used about 130 times as the only target: enemy AI, the chase King, the throne boss, the feast King, hazards, pickups, checkpoints, triggers, arenas and traps.
2) Several states stop the whole simulation by returning early from Level3D.update (level.ts:786-824): results, the item popup, pause, hitstop (`freeze`) and the death slow-motion (`slowT`). On the host these would stop the shared world.
3) Respawn rebuilds the whole level (level.ts:770-774 calls `game.go(new Level3D(id, idx, cp, seen))`), and every story transition writes to the local `save` (game.ts:59-68).

Recommended split:
- **Host only:** detecting triggers, exit zones, arenas, traps and checkpoints against all heroes; the world side of the scripts (`FeastKing3.dangerous`, `noticed`, `forceSnack` and `primeFeeding`; `KingChaser3.active`, `speed` and `front`; `BreakWall.burst`; `KingBoss3.manualRoot`, `start()` and `onDefeat`); and every story transition.
- **All clients, locally, on a host event:** the 13 scripts in SCRIPTS3 as presentation (camera, dialog, the local hero's auto/hidden/faceYaw/forceState, NPC animation, item-get), the start scripts, the exit scripts and the boss victory scene.
- **Local only:** pause overlay, hitstop, slow-motion, item popup, HUD, camera, results card, shop purchases, hints, settings.

Events the host should send: `level_load`, `level_begin`, `script{id}`, `arena_start/wave/done{key}`, `checkpoint_lit{idx}`, `faller_spawn`, `exit_ready/level_exit`, `boss_defeated`, `team_wipe/level_restart`, `goto{storyIndex}`. Events clients should send: `hero_state` (the HeroAnim already built in Player3.sync, player.ts:512-529), `hit{netId, dmg, atkId, kind}`, `noise`, `player_down`, `script_done`, `results_done`, `ready`.

Every dialog line waits for local confirm input (dialog.ts:53-56). So each client either runs cutscenes at its own pace while the host keeps the world frozen until it gets `script_done` from everyone (or a timeout or skip vote), or the host relays a `dialog_advance` to all.

## Risks
- Full-rebuild respawn (level.ts:770-774, a new Level3D through game.go) cannot coexist with a shared world. It needs an in-place per-hero respawn, plus a host-driven team restart.
- Local states stop the host's whole world: early returns in Level3D.update for results (786), item popup (792), pause (813) and hitstop (824), plus slowT on death (822). On the host these freeze the game for everyone unless the update is split into tickWorld and tickLocal.
- The host's local cutscene state (letterboxTarget > 0.5 makes enemies only sync, level.ts:830; inCutscene gates triggers and arenas) currently doubles as world state. It must become an explicit worldCutscene flag, or the world freezes or unfreezes based on the host's dialog pacing.
- Dialog advances on local input (dialog.ts:53), and scripts block on it. Without a shared cursor or a script_done barrier, clients drift apart in story beats.
- Scripts mix world mutation with presentation (feast_intro, feast_king, exit_feast, chase_intro, startChase, exit_chase, throne_intro, throne_retry, throne_victory). Running them unchanged on every client would make each client mutate its own copy of host-owned actors.
- About 130 single-target `L.player` references across enemies, the chase King, the throne boss, the feast King, the spaghetti monster, objects, bombs and breakables. Every AI and hazard needs a hero-set or target-selection API on the host and victim-side hit tests on clients.
- game.story writes to the local save (game.ts:62-65), so joining someone's room would overwrite the client's solo progress. Late joiners also lack the abilities later levels require (slingshot, doubleJump, dash, fork), so a chapter-based loadout floor is needed.
- Host tab backgrounded means rAF stops (main3d.ts:101) and the authoritative world stops for everyone. Slow hosts lose time through `acc = 0` (main3d.ts:99). Needs a hidden-tab tick fallback or host migration.
- Non-deterministic world build and timing: Breakable3 rand rotY and jam colour (breakables.ts:26-28), Noodle3 `t = rand(0,10)` swing phase, npc `t`, and `L.t` starting at local construction. Time-driven hazards and colliders differ per client unless seeded and clock-synced.
- game.go drops a transition if one is already pending (game.ts:46), and scenes do not update during fades (game.ts:87). Network message handling must live outside scenes, and host gotos must be queued.
- Runtime-spawned enemies (boss crew, splitters, addEnemy after build) have key = null, so they need host-assigned netIds. Kill and loot attribution needs a killerId on hit events. Enemy loot currently uses the host's magnet and slingshot (enemies.ts:116-119).
- Module-level singletons (LIB_PORTAL, CHASE_SMASH, FEAST_SPOTS, CHASE_SPOTS in levels.ts; STATS WeakMap in level.ts:65; global input, save, audio, game) block running a host and a client in one page, so co-op testing needs two tabs with a loopback transport.
- Gamepad: pollPad overwrites stick values per pad (input.ts:162-163), and PADMAP assumes the standard mapping. Bluetooth DualShock or DualSense may show up non-standard or as several entries, which is relevant to the user's first request.
