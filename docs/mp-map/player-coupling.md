# player-coupling

## Summary
I read every file under src/three/game and src/ui/hud.ts in full, except levels.ts, where I grepped all L.* calls (it has no player reads). I also grepped camera.ts, lighting.ts, physics/, world/, scenes3d.ts and dev/. The code assumes a single hero through `Level3D.player` (level.ts:110, a Player3). AI, hazards and story code read `L.player` directly about 200 times. Nothing outside src/three/game and hud.ts reads the player: camera, lighting, world, physics and scenes3d have no player refs; camera/sun are fed the local hero by level.ts:865-866. There are 21 direct `p.hurt` call sites, 2 internal `die()` call sites (player.ts:294, 464), 3 `hazardHit` call sites, 8 places that write `grabbedBy`, and 8 knockback writes after hurt. Recommended API, used in the change column: `L.local` (the local Player3, with `L.player` kept as an alias), `L.heroes` (the local hero plus RemoteHero puppets behind a HeroLike interface: id, pos, vel, center(), body.r/h, yaw, dead, hidden, control, invuln, dashing, grabbedId, atk/atkT/atkId, hp/maxHp), `L.alivePlayers()`, `L.targetFor(enemy)` (sticky, nearest visible alive hero with control), and `net.hurt(pid, {dmg, from, kb?, knockT?})`. Player3.hurt should also take an optional kb that is applied only when the hurt is accepted, so the owner stays authoritative over its own hp and invulnerability. Six structural blockers are not plain player reads. (1) The Level3D.update early returns (hitstop freeze, death slowT, pause, popup, and the letterbox freeze) stop the whole simulation, enemies and scripts included, which would freeze the host world for everyone. (2) atkId is a per-hero counter that starts at 0, so hit dedup keyed on it collides across players. (3) grabbedBy holds object references; the boss grab reads local input (throneBoss.ts:1092); release reasons read L.player.grip. (4) Every dropPickup rolls loot with the host's save, but the plan says loot is per player. (5) respawn() rebuilds the whole level. (6) Every client simulates its own hero's physics, so collider state must be identical on all clients: arena gates, boss hand colliders, BreakWall, chaser smash props, breakables, crumbly platforms. Story scripts mix local-hero staging with world-authoritative actions (boss.start, ch.active, k.dangerous, wall.burst, endLevel), so they need splitting.

## Risks
- Host world freezes for everyone: Level3D.update returns early or scales dt on the local-only states hitstop/freeze (level.ts:824), death slowT (822), pause (813), popup (792), results (786). The enemy freeze also keys on the local letterboxTarget (830), as do Soldier3.sense (enemies.ts:233) and SpagMonster (spaghettiMonster.ts:70). Without restructuring, a host hit, pickup or pause stalls every client.
- atkId is a per-Player3 counter starting at 0 and is the hit-dedup key in Enemy3.lastHit, BossHand.hit, faceHit, BowlBall.hitIds, SpagMonster.hitIds and Breakable3.lastAtk. Two players' swings with the same id are silently ignored unless the id is namespaced by slot.
- grabbedBy holds live object references (Noodle3, or the Grabber cast as Noodle3) and release() is called from Player3. The boss grab reads LOCAL input (throneBoss.ts:1092), and onGrabRelease reads L.player.grip (793). Grabs need ids, a reason field and an owner-side GrabProxy whose tip comes from the snapshot.
- Instanced loot conflicts with the current code: every L.dropPickup runs where the enemy dies (the host) and rolls with the host's save (magnet, slingshot) in enemies.ts:116-119, breakables.ts:61-64, level.ts:724-725, throneBoss.ts:340, bossParts.ts:205 and spaghettiMonster.ts:284-285. All of them must become loot events rolled per client.
- respawn() (level.ts:770) rebuilds the entire Level3D through game.go. That cannot work with a shared host world; in-place respawn or revive plus a host-driven party-wipe restart is required.
- Each client simulates its own hero's physics, so collider state must match exactly: arena gate cols, the boss hand h.col (tag 'king'), the spaghetti monster cyl col, BreakWall col, chaser smash cols, breakable colliders and crumbly platforms (level.ts:365/374). Any desync lets a hero walk through or get stuck inside geometry.
- Story scripts interleave world-authoritative actions (boss.start, ch.active/front/speed, k.dangerous/noticed/forceSnack, wall.burst, L.endLevel) with local hero staging and camera work in one coroutine. They must be split into a host part and a broadcast per-client part, and dialog pacing must not block the host simulation.
- The stealth AI only hears the local hero's noises (player.ts:147/216/233/307). Remote heroes are silent and invisible to Soldier3 unless noises and the remote proxies' hidden/control/atk fields are injected on the host.
- Noodle3.t = rand(0, 10) (objects.ts:253) makes swinging-noodle timing hazards differ between clients unless seeded or replicated.
- Balance and design: the 'at most 2 attackers' cap (enemies.ts:347), the bookSwoopT throttle, the boss summon cap (alive < 3), boss and enemy HP, and the chaser's single 'gap' were all tuned for one hero. Per-player abilities live in each client's save, so a friend without double jump or dash cannot clear bowling balls or chase pits. Party ability parity or loaner abilities need a decision.
- Exit zone and arena activation on 'the' player will strand teammates: arena bars close around whoever entered first, and the level completes as soon as one hero touches the exit.
- Some AI keeps references to the target's live position vector (Meatball3 tgt = p.pos at enemies.ts:930; lastSeen copies). Swapping the target object mid-action must be handled explicitly by retargeting.
